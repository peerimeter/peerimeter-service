# Repository guidance

This is the independent `peerimeter-service` Go repository. The sibling `../.github` directory is a separate Git repository and contains the shared plan and progress tracker. Consult those documents for project decisions, then check this repository's current code and README for actual behavior and verification.

## Project map

- `cmd/peerimeter-service/`: HTTP service entry point.
- `internal/`: API, authentication, configuration storage, and service lifecycle.
- `.github/workflows/`: service CI and GHCR release pipeline.
- `Dockerfile`: multi-stage production image.
- `docs/index.html` and `docs/CNAME`: public setup guide for source and Docker deployments at `service.peerimeter.app`.

## Development

- Keep this module independently buildable. Keep `go 1.27` in `go.mod`; use `.go-version` to pin the exact development/CI patch release.
- Before changing code, read the relevant implementation and tests. Keep changes narrow and document limitations accurately.
- Never commit API keys, private keys, production credentials, or generated usable configurations.
- Follow `../.github/docs/repository-conventions.md` for branches, commits, PRs, checks and completion claims.
- Keep GitHub repository settings aligned with the shared [Peerimeter AGENTS.md](https://github.com/peerimeter/.github/blob/main/AGENTS.md): enable auto-merge and branch updates, delete head branches after merge, and allow rebase merges only.
- Run relevant Go tests/build checks for implementation changes and report checks that could not run.
- Keep in-memory state, JSON file persistence and API contracts explicit; do not imply transactional or multi-instance guarantees beyond the implementation.
- Pin GitHub Actions to explicit release tags and keep `.github/workflows/actions.lock` generated by `gh actions-lock`; it records and verifies each immutable commit SHA. Never hand-edit the lock file.
- Version-tagged container images are published to GHCR. Do not publish untagged images from pull request workflows.
